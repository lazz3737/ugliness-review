# 案例 003 · 审自己的文档：726 条直引号与 linter 的误报

- **日期**：2026-11-09
- **类型**：改判
- **产物类型与域**：本仓库全部 Markdown · D 域
- **原判词**：首次自审，`copy_lint.py` 报 726 条 D-R5 违规，绝大多数为中文语境直引号。
- **反对理由**：其中大量引号出现在 YAML frontmatter、代码块和“错误写法示例”里，属于语法引号，不是正文。
- **最终裁决**：正文直引号按 217 行批量修正为“”；工具升级——跳过 frontmatter、fenced code、inline code，且不再扫描 `.json`（JSON 的引号是语法）；剩余 3 条“引号本身当例子”改为代码标记。
- **归因**：执行错——工具没有区分“正文”与“代码”。
- **修订动作**：`copy_lint.py` v0.2.0；复判违规归零，保留 271 条 advisory（空格 / 句长 / 黑名单）。
- **教训**：审丑工具先审自己；误报和漏报一样会毁掉判词的可信度。
