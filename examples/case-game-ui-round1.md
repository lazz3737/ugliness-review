# 判卷样例 · 某小游戏首屏（节选）

> 匿名化说明：项目名、角色、剧情与商业信息已替换；像素坐标为 1440×900 原图上的近似值。
> 判据：本仓库 A/B 两域条款 v0.1；参数来源：条款默认值（项目度量表未随图提供，与项目参数冲突时以项目为准）。
> 用途：演示单张截图能判到什么程度，以及哪些条款必须靠取证工具补检。

## 元信息

- 对象：游戏首屏截图 1 张（1440×900）
- 模式：交付模式
- 判据版本：0.1.0

## A 域 · 道具与场景

**【A-R1 一把尺子】【违规】**
证据：门框总高约 260px（y≈215–475），角色坐姿高约 335px（y≈395–730）——坐着的人比门还高，窗、门、角色不在同一张度量表上。
修法：按度量表把门放大到角色站高的约 1.3–1.5 倍，窗台高同步归位；先建表再摆件。

**【A-R4 接触与落地】【违规】**
证据：角色臀部与圆垫之间无接触阴影；桌面与地面之间、四条桌腿下均无落影，物件像贴纸平铺。
修法：每个接触点补软阴影或 AO，宁重勿无；圆垫与地板之间补过渡。

**【A-R3 材质语言统一】【存疑】**
证据：全屋平涂矢量语言，唯独角色右侧（x≈1000–1160，y≈430–500）有一块大软径向阴影，像错位的投影或污渍。
修法：是投影则收回脚下并收紧边缘，否则删掉。

**【A-R2 形随功能】【存疑】**
证据：桌上白色椭圆物（x≈505–560，y≈595–615）遮名后无法判断是空碗、空盘还是信封。
修法：给一个功能开口或内容物。

**【A-R6 色彩克制】【存疑】**
证据：青窗、红帽、橙食物三处彩色同时在线；红帽是否唯一信号色需项目拍板。

**【A-R8 叙事一致】【存疑】** 全屋零磨损、零使用痕迹。
**【A-R7 剪影与 64px】【存疑（未检）】** 单张截图无法验证，需剪影墙与 64px 缩略墙补检。
**【A-R9 切线禁止】【存疑】** 头发上缘与窗台线平行贴近（间距约 40px），粉窗右框与头部右缘近似同线，需 3× 放大复核。
**【A-R5 细节预算】【通过】** 息区充足，细节集中在桌与窗。
**【A-T1 疏密节奏】【通过】** 无等距散点。

## B 域 · UI 与版式

**【B-R1 一屏一主】【违规】**
证据：最大字号（约 40px）在左上信息卡；视觉面积最大、含唯一 CTA 的是右上愿望卡；两处同时在喊。
修法：选定愿望卡为主角，信息卡降为次级条带。

**【B-R2 字号层级】【违规】**
证据：约 5–6 档：40 / 30 / 20 / 18 / 16 / 15px；级差 1.33、1.5、1.11、1.13，两处低于 1.4×。
修法：收敛到 32 / 22 / 15 / 12 四档。

**【B-R3 字体与图标】【违规】**
证据：全站单一圆体无衬线，没有"说话体"；emoji 已清干净。
修法：补说话体（标题/刊名）与干活体两个角色，写进项目参数。

**【B-R6 留白预算】【违规】**
证据：卡片与按钮距屏幕左右边缘约 40px（2.8%），条款要求 ≥5%（72px）。
修法：边距提到 72px；若项目 HUD 坚持 40px，写进项目参数槽并在报告注明豁免。

**【B-R7 UI 色彩与世界同源】【违规】**
证据：UI 是纯白大圆角卡 + 软投影的"网页对话框"语法；卡片比墙体更亮，没有指向世界物件的材质血缘。
修法：卡片改纸色或家具同源色并给色值；描边从世界色卡取。

**【B-R8 廉价五件套】【违规（命中 2 项）】**
证据：② 全站统一软投影（两卡 + 两按钮）；④ 满屏等大圆角胶囊（两卡 + 两按钮 + CTA 描边胶囊）。
修法：先减后加——去投影改纸边描线，圆角按层级分档（卡 16 / 按钮 8）。

**【B-R9 版式语法统一】【存疑】** 单屏无法验证并排一致性，需母版 + 第二屏复核。
**【B-T1 纸感与印刷材质】【存疑】** 与 A-R3 一起定档。
**【B-R4 中文排版】【通过】** 全角括号、中西文留空目测合格。
**【B-R5 网格与对齐】【通过】** 左缘基本对齐；圆角体系问题归 B-R8。

## 修复优先级

1. UI 整体语言（B-R7 + B-R8 + B-R6）：投影、圆角、边距、色值一起定，改一次影响全屏。
2. 比例（A-R1）：门比坐着的角色矮，一改房间立刻立住。
3. 落地（A-R4 + A-R3 错位阴影）。
4. 字号与字体（B-R2 + B-R3）。

## 结论

红线 8 条未清零，**不许交付**。存疑 8 条移交拍板；改完同机位复拍，逐条对原判词复判。

## 取证缺口（给 v0.2 的反馈）

- 单张截图让剪影墙、64px 缩略、灰度三项取证全部缺席，只能目测"约 X px"。
- B-R2、B-R6 这类数值条款完全可以脚本量——采集脚本优先级应高于再写条款。
