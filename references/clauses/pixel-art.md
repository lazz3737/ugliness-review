# 条款域 · H 像素画

> 只回答“什么算不及格”，不回答“什么值得画”。
> 分档：**R = 红线**（命中必返工）；**T = 倾向**（可商量，下不为例要记账）。
> 参数：像素密度（PPU）、色板、描边策略、字库、帧率由项目提供（见 `project-params.md`）。
> 判卷对象：**原生分辨率截图 + 整数倍放大图 + 64px 缩略墙 + 色板导出**。

## H-R1 整数缩放与像素网格

- **条款**：像素资产只允许整数倍缩放（1× / 2× / 3×…），采样用最近邻；位置与尺寸取整，禁止任意比例缩放与亚像素定位。
- **为什么**：非整数缩放会让像素块大小不一、边缘发虚，整个画面读起来就是“糊的”，这是像素风最基础的破绽。
- **违反的样子**：窗口拉到 1.5×，像素块 1px/2px 交替；UI 出现 0.5px 边框；图标位置落在半像素上。
- **修法**：画布按整数倍适配（多出的空间用 letterbox）；渲染用最近邻（CSS `image-rendering: pixelated`）；所有坐标取整。
- **出处**：像素画整数缩放惯例；游戏像素渲染实践。

## H-R2 像素密度统一（PPU）

- **条款**：同一场景内所有资产与 UI 采用同一像素密度（每单位像素数一致）；不混入高分辨率、矢量或平滑渲染素材。
- **为什么**：密度不一致等于两套世界；角色是像素画、卡片是平滑网页，观众一眼看出“拼的”。
- **违反的样子**：角色 32px 高、道具 128px 精修；UI 卡片带平滑圆角与软阴影；贴图与像素角色同框。
- **修法**：定 PPU 基准，所有资产按基准重采样；UI 也走像素网格。
- **出处**：像素画管线规范。

## H-R3 描边策略统一

- **条款**：全项目同一套描边规则：全描边 / 选择性描边 / 无描边，三选一；描边宽度统一 1px；描边颜色取自项目色板。
- **为什么**：描边是像素画里最显眼的“语言”。角色有描边、场景没有，主体就像贴上去的。
- **违反的样子**：角色 1px 实线描边、桌椅零描边；描边用色板外的纯黑；不同资产描边粗细不一。
- **修法**：写进美术规范；用放大图逐件检查边缘；描边色从色板深色档取。
- **出处**：像素画 selective outlining 惯例。

## H-R4 色板容量

- **条款**：项目色板固定（示例 ≤32 色），资产不得使用色板外颜色；渐变必须用抖动（dithering）实现，不用连续渐变工具。
- **为什么**：色板是像素画的“调色纪律”；颜色一多，画面立刻变成缩小的插画，“像素感”消失。
- **违反的样子**：每件资产一套色；用渐变工具画出平滑过渡；色板外出现一个高饱和亮点。
- **修法**：建 `.pal` / `.gpl` 色板文件并在工具里锁定；导出前用取色器全图扫一遍。
- **出处**：像素画色板纪律；限制色板实践。

## H-R5 无抗锯齿与亚像素

- **条款**：像素资产边缘不出现半透明抗锯齿；旋转、缩放一律最近邻；禁止亚像素位移造成抖动。
- **为什么**：抗锯齿边缘是“像素风”最容易被判死刑的信号——它同时毁掉清晰度与风格。
- **违反的样子**：角色边缘一圈半透明灰；旋转 30° 后糊边；动画里角色每帧轻微抖动。
- **修法**：导出时关闭抗锯齿；变换后重采样为最近邻；动画位移取整。
- **出处**：像素画技术规范。

## H-R6 像素字库

- **条款**：文字使用统一像素字库，字号为字库原生尺寸的整数倍；不混用系统字体平滑渲染；中文与西文同一字库风格。
- **为什么**：平滑字体和像素画面放在一起，像给像素游戏套了个网页；字号非整数倍会直接糊。
- **违反的样子**：UI 用系统黑体 9px，边缘发虚；中文像素字与英文圆体混排；9px/11px/15px 三种非字库倍数。
- **修法**：选一套支持中文的像素字库（或自制），锁定 8/16/24 等整数档位。
- **出处**：像素字库实践。

## H-R7 剪影与明度对比

- **条款**：主体与背景明度差 ≥15%（像素尺度更容易糊）；64px 缩略仍可辨认；剪影墙 1 秒可读。
- **为什么**：像素场景明度容易挤在一起；缩略图下主角消失，等于没有主角。
- **违反的样子**：浅色角色站在浅色墙前，64px 缩略后只剩一团；剪影墙认不出角色姿态。
- **修法**：`scripts/evidence.py` 出剪影墙与 64px 墙；调明度或加 1px 描边。
- **出处**：A-R7 在像素域的延伸；像素对比实践。

## H-R8 动画帧纪律

- **条款**：帧率与帧数全项目统一（示例 8fps 或 12fps），循环帧数固定；帧间位移为整数像素；不混用不同帧率的素材。
- **为什么**：帧率混杂会让动作“一卡一卡”；亚像素位移会让整张画面抖。
- **违反的样子**：走路 8fps、待机 30fps；位移 0.5px 导致抖动；循环多一帧造成抽搐。
- **修法**：建动画规格表；导出抽帧检查（C/G 域方法）。
- **出处**：像素动画惯例。

## H-T1 抖动图案统一（倾向）

- **条款**（倾向）：抖动图案全项目统一（Bayer / 随机 / 手绘），同一材质只用一种抖动方式。
- **修法**：把抖动笔刷固化进工具预设。
- **出处**：像素画抖动实践。

## H-T2 风格纯度（倾向）

- **条款**（倾向）：不混入矢量、3D 渲染或照片素材；若确需混用，必须在全项目统一处理并显式声明。
- **修法**：素材入库前过风格审查；混用方案写进项目参数。
- **出处**：像素风一致性实践。

## 与其它域的关系

- **A-R3 材质语言**：像素画没有 PBR 材质，本域用 **H-R3 描边策略 + H-R4 色板容量** 替换“材质方言”；判卷时不再引用 A-R3。
- **A-R7 剪影 / 64px**：由 **H-R7** 继承并加严（明度差 ≥15%）。
- **C 域动画**：动作结构照 C 域判，帧率与整数位移照 **H-R8** 判。
- **B 域 UI**：版式照 B 域判，但字体与图标必须走 **H-R6** 像素字库。

## 取证与判卷

- **整数倍放大图**：截原图后放大 3×（最近邻），像素块应大小一致（H-R1）。
- **密度对照**：角色与场景同屏放大图并排，看“一个像素块多大”是否一致（H-R2）。
- **描边检查**：放大图逐件看边缘（H-R3 / H-R5）。
- **色板导出**：取全图颜色数，与项目色板比对（H-R4）。
- **字库检查**：UI 文字放大 4×，像素边缘应硬、字号应为字库倍数（H-R6）。
- **剪影 / 64px 墙**：`scripts/evidence.py silhouette` / `thumbs`（H-R7）。
- **抽帧**：动画抽帧看帧率与位移（H-R8）。

## 判卷样例（匿名化）

> 某像素风小游戏首屏，首轮判卷节选。

**【H-R2 像素密度统一】【违规】**
证据：角色与场景为像素渲染，右上纸条卡与按钮为平滑圆角 + 软阴影（放大 3× 无像素块），同屏两套渲染语言。
修法：卡片改为像素边框与硬阴影；所有 UI 按 PPU 基准重绘。

**【H-R3 描边策略统一】【违规】**
证据：角色全身 1px 描边（发际 #C2A780），桌、门、窗为零描边。
修法：统一“选择性描边”策略并写进规范；场景关键轮廓补 1px 描边。

**【H-R6 像素字库】【违规】**
证据：UI 文字为系统字体平滑渲染，字号 9px 非字库整数倍，放大 4× 边缘发虚。
修法：换像素字库，字号锁 8/16 两档。

**【H-R1 整数缩放】【存疑】**
证据：窗口 1440×900 下素材按 1.5× 呈现，放大图里像素块 1px/2px 交替。
修法：改为 1× 或 2× 整数适配后复判。

**结论**：红线 3 条未清零，不许交付。
