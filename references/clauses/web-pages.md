# 条款域 · E 网页

> 只回答"什么算不及格"，不回答"什么值得做"。
> 分档：**R = 红线**（命中必返工）；**T = 倾向**（可商量，下不为例要记账）。
> 参数：断点、字体栈、色卡、触控目标、对比度标准、动效预算由项目提供（见 `project-params.md`）。
> 判卷对象：**截图三档（390 / 768 / 1440）+ 交互态截图**，不判手感与后端。

## E-R1 首屏说清

- **条款**：首屏 5 秒内能回答三件事：这是什么、给谁用、下一步做什么。答案必须在首屏内可见，不许靠滚动才出现。
- **为什么**：首屏是唯一"所有人都看到"的一屏。首屏说不清，后面写得再好也没人看。
- **违反的样子**：首屏只有一张大图和一句诗；用户要滚三屏才知道产品是干嘛的。
- **修法**：把"是什么/给谁/下一步"写进首屏主标题、副标题、主按钮三件套；做完 5 秒测试再交付。
- **出处**：GOV.UK 首屏实践；NN/g 首屏与滚动研究；taste-skill（hero 先说清）。

## E-R2 一屏一节（每个 section 一个主张）

- **条款**：每个区块只主张一件事；在 1440×900 的一个屏高内完成这个主张（标题 + 证据 + 一个动作），不把两件事挤进同一屏。
- **为什么**：滚动是节奏。一屏两件事，读者两件都没记住。
- **违反的样子**：一个区块里同时放"功能介绍 + 客户评价 + 价格表"；每屏都塞满，没有呼吸。
- **修法**：按"一句话主张"切分区块；一节一屏；节与节之间留出整块留白。
- **出处**：taste-skill（one section per screen、左右等边）；design-craft（一屏一节）。

## E-R3 响应式与断点

- **条款**：至少在 390 / 768 / 1440 三档下无横向滚动、无裁切、无重叠、无文字截断；断点位置写进项目参数，不许"看着调"。
- **为什么**：手机是主战场。任何一个断点下的横向滚动条，都会被当成"没做完"。
- **违反的样子**：390px 下按钮被裁掉一半；768px 下标题与配图重叠；表格撑破容器。
- **修法**：三档截图逐档验收；用 `scripts/evidence.py` 的网格叠加查边距；布局用流式 + 少量断点，不用固定像素堆。
- **出处**：W3C 响应式设计实践；web.dev 布局基础。

## E-R4 状态覆盖

- **条款**：每个可交互元素必须有 hover / focus / active / disabled 四态；数据区域必须有 loading / error / empty / success 状态。只做了默认态的，视为未完成。
- **为什么**：状态是交互的语法。没有状态，用户不知道"点了没有、能不能点、点了会怎样"。
- **违反的样子**：按钮 hover 无变化；表单提交后没有任何 loading；列表空的时候一片空白。
- **修法**：建一张"组件 × 状态"表，逐格补；截图逐态验收。
- **出处**：web-design-guidelines（Vercel）；NN/g 系统状态可见性；Material/iOS HIG 状态规范。

## E-R5 可访问性下限

- **条款**：正文对比度 ≥4.5:1，大字与非文本 ≥3:1；键盘可到达所有交互元素且焦点可见；图片有 alt（装饰图 alt=""）；尊重 prefers-reduced-motion；不用颜色作为唯一信息通道。
- **为什么**：可访问性是及格线，不是加分项；对比度不够的页面在户外、老屏幕、色弱用户那里直接不可用。
- **违反的样子**：浅灰字配白底；按钮只有 hover 才显示；表单错误只用红色边框提示。
- **修法**：`python scripts/evidence.py contrast <img> --fg x,y --bg x,y` 逐点测；键盘 Tab 走一遍；错误提示同时给图标与文字。
- **出处**：WCAG 2.2（AA）；W3C WAI；web.dev accessibility。

## E-R6 触控目标

- **条款**：移动端所有可点元素 ≥44×44px（或项目声明的等效尺寸），相邻目标之间留 ≥8px 间距；文字链在段落内除外，但行高要够。
- **为什么**：手指不是鼠标。目标太小，误触率直接上升，用户会把"点不中"记成"这站难用"。
- **违反的样子**：关闭按钮 16px；一排图标按钮彼此贴住；底部导航项挤在一起。
- **修法**：给点击区加透明内边距；列表项整行可点；截图量一遍尺寸。
- **出处**：WCAG 2.2 Target Size；Apple HIG 44pt；Material 48dp。

## E-R7 真实内容

- **条款**：交付稿里必须是真实照片、真实界面截图、真实文案、真实数据；占位内容必须显式标注为占位（如"示例数据"），不许把编造的用户评价、logo、数据当成品。
- **为什么**：假内容会掩盖真实问题（图片比例、文案长度、数据密度），也会让页面一眼"模板感"。
- **违反的样子**：Lorem ipsum 没换；编造的"来自 500 强企业的信赖"；盗用的品牌 logo；虚构的用户头像。
- **修法**：没有真图就先用项目素材库的授权图并标注；没有数据就不放数据模块；交付前全局搜一遍占位词。
- **出处**：taste-skill（真实照片与真实 UI）；hallmark anti-patterns（fabricated stats）；Hmbown/taste（specifics from the source）。

## E-R8 稳定与性能

- **条款**：图片与视频必须写死尺寸或比例（防布局抖动）；字体加载不许造成不可读窗口；首屏不因慢网出现大面积空白或错位；不做会拖垮滚动的重型特效。
- **为什么**：抖动与慢，是"廉价"的体感来源；用户感知到的不是性能数字，是"这页不靠谱"。
- **违反的样子**：图片加载时文字被顶下去；字体切换时整页跳一下；首屏一张 5MB 大图；滚动时掉帧。
- **修法**：img 写 width/height 或 aspect-ratio；图片压缩到目标尺寸的 2× 以内；字体 `font-display: swap` + 回退栈；上线前跑 Lighthouse。
- **出处**：web.dev Core Web Vitals（CLS / LCP）；W3C 图片尺寸建议。

## E-R9 导航与位置感

- **条款**：当前所在位置必须可见（导航高亮 / 面包屑）；返回行为与浏览器一致；链接与按钮视觉可区分（链接可辨、按钮像按钮）；深层页面可直接访问（深链不 404）。
- **为什么**：用户随时可能从任何一页进来。不知道"我在哪、怎么回去"的页面，会被直接关掉。
- **违反的样子**：导航没有当前态；点"返回"跳出站外；整页文字都是链接色；分享出去的链接打开是首页。
- **修法**：导航加当前态；链接统一带下划线或明确色；路由支持深链并做 404 兜底。
- **出处**：NN/g 导航与位置感；GOV.UK 导航模式。

## E-R10 表单与输入

- **条款**：每个输入有常显 label（不是 placeholder 当 label）；错误就地提示并说明怎么改；提交失败不丢已填内容；必填项有标记；能自动完成的字段加 autocomplete。
- **为什么**：表单是转化发生的地方，也是用户最容易被气走的地方。
- **违反的样子**：placeholder 一输入就消失；错误只在顶部弹一句"请检查表单"；刷新后全部重填。
- **修法**：label 常显；字段级错误提示；本地暂存输入；按 E-R5 保证颜色之外还有文字提示。
- **出处**：GOV.UK 表单设计模式；NN/g 表单可用性；WCAG 表单规范。

## E-R11 模板指纹黑名单

- **条款**：以下为"AI 生成感 / 模板感"高频指纹，命中 ≥2 项即返工：
  ① 紫蓝渐变大面积铺底；② 玻璃拟态叠加；③ 三张等大圆角卡片并排当万能版式；④ 满屏居中排版；⑤ 全场 fade-up 入场；⑥ 假浏览器 / 手机 chrome 装饰；⑦ 发光描边字；⑧ 无意义的编号 01/02/03 标记。
- **为什么**：这些是"默认值"的指纹；单看都"像样"，合起来就是"没人在管"。
- **违反的样子**：紫渐变 hero + 三卡 + fade-up 三件套齐活。
- **修法**：先减后加；每处装饰问"它编码了什么信息"；与项目视觉语言对齐（如本库的纸感手帐风：禁阴影堆层次、禁荧光色当 UI 主色）。
- **出处**：Impeccable / frontend-design 的 AI Slop 清单；hallmark anti-patterns；本库《纸感手帐风设计语言》禁忌节。

## E-T1 动效克制（倾向）

- **条款**（倾向）：一屏一个编排时刻（入场或滚动揭示二选一）；交互反馈优先于装饰动画；尊重 reduced-motion；不做常驻漂浮/呼吸动效。
- **修法**：删到只剩一个" memorable moment"；其余用即时反馈。
- **出处**：frontend-design（one orchestrated moment）；UI 动效设计（曲线/时长/距离/编排）。

## E-T2 视觉与文案同源（倾向）

- **条款**（倾向）：图片风格、字体角色、文案语气三者同一声音；纸感项目不许出现塑料感插图，科技项目不许出现手写体口号。
- **修法**：交付前把首屏图、标题、按钮放一起读一遍，像不像同一个产品。
- **出处**：本库《纸感手帐风设计语言》（字体角色 / 色彩角色）；Mailchimp voice & tone。

- **三档截图**：390 / 768 / 1440 各一张，逐档查 E-R3；用 `scripts/evidence.py grid` 叠边距线。
- **状态截图**：每个组件截默认 / hover / focus / disabled；数据区截 loading / empty / error。

- **占位词搜索**：全局搜 lorem、占位、示例、TODO（E-R7）。

## 判卷样例（匿名化）

> 某落地页首轮判卷节选。

**【E-R3 响应式与断点】【违规】**
证据：390px 截图出现横向滚动条，价格卡第三列被裁掉约 1/3；1440px 下首屏正常。
修法：断点降到 768 时改为单列；容器宽度用 max-width + 百分比；三档复拍。

**【E-R4 状态覆盖】【违规】**
证据：主按钮只有默认态，hover 与 disabled 无视觉差异；订阅表单提交后无 loading，用户可重复点击。
修法：补 hover/focus/active/disabled 四态；提交时按钮进入 loading 并禁用。

**【E-R8 稳定与性能】【违规】**
证据：hero 图未写尺寸，慢网下标题被顶下 180px；字体切换时整页闪烁一次。
修法：img 写 aspect-ratio；字体加 `font-display: swap` 与回退栈。

**【E-R11 模板指纹】【违规（命中 3 项）】**
证据：①紫蓝渐变 hero、③三张等大圆角卡片、⑤全场 fade-up 入场——三件套齐活。
修法：先减——去渐变换项目色卡；卡片改为"一主两次"的层级；只保留一个入场编排。

**【E-R5 可访问性】【存疑】**
证据：正文灰字（#8A8A8A）配白底，目测接近临界；未做键盘走查。
修法：先跑 contrast 测量，再 Tab 走一遍后复判。

**结论**：红线 4 条未清零，不许交付。
