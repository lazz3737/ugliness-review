# 判词格式与纪律

## 三态判定

- **通过**：判据满足，可复核。
- **存疑**：证据不足，或需要人拍板。必须写清"缺什么证据 / 要谁拍板"，不许含糊。
- **违规**：判据被违反。必须附证据。

## 四段式判词

```
【A-R3】【违规】
【证据】BURGER 高光锐利、表面无磨损，与哑光家具并排；见 evidence/batch2/burger_3x.png
【修法】统一 roughness ≥ 0.75，与基准件三件套并排复核后再入库
```

四条缺一不可：条款号、判定、证据、修法。

## 判词纪律

- 只判"不及格"，不说"美不美"；不写"更好看""更高级"；不引用趋势。
- 证据位置精确到"哪件资产、哪块区域、几倍放大"。
- 修法要可执行：给参数、给动作、给验收方式，不写"优化一下"。
- 一条判词只判一个条款。一个缺陷命中多条时，按最重的那条记，其余备注。
- 拿不准就进"存疑"，不擅自替用户拍板。

## 报告结构

1. **元信息**：判卷对象、日期、判据版本、参数来源（项目参数 / 默认值）。
2. **逐条判词**：按域排列。
3. **汇总表**：域 / 红线违规数 / 存疑数。
4. **修复优先级**：按影响面排序（影响每一屏的排最前）。
5. **存疑移交**：逐条列给用户拍板。
6. **结论**：红线是否清零；**未清零时结论必须是"不许交付"**。

## 复判

- 在**同一位置、同一机位、同一尺寸**复拍。
- 逐条对原判词输出：条款 / 原判 / 复判 / 证据。
- 修法引发的新问题照常判，不因"是修出来的"而放行。
- 全部红线清零后，才允许写"可交付"。

## 否决立法

用户否决判词时，不要辩护，也不要立刻改口。走三步：

1. **记录案例**：原判词、用户的否决理由、最终裁决；写进 `cases/`（模板与命名见 `cases/README.md`）。
2. **归因**：是条款错了（判据不成立）？参数错了（项目参数不适用）？还是执行错了（取证/判断有误）？
3. **回写**：改条款、改参数或改取证流程，并在 CHANGELOG 留痕。

条款每两周审一次；长期不命中的条款降级或删除。**否决是机制的学习数据，不是失败。**

## 隐私与公开

- 判卷报告默认只在项目内流转。
- 对外发布示例必须匿名化：项目名、角色、剧情、商业信息一律替换。
- 证据图同样要检查是否含隐私信息。
